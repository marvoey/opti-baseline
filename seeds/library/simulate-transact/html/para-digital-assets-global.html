Digital Asset API Integration Setup

Asset managers seeking to incorporate digital asset holdings — including tokenized securities, stablecoins, and on-chain fund units — into their existing CIBC Mellon reporting framework can initiate API integration through the Digital Asset Services onboarding workflow. This process covers API key provisioning, blockchain network configuration, wallet enrollment, and reconciliation scheduling.

Prerequisites

  • Existing CIBC Mellon client relationship with an active custody or fund administration agreement
  • Digital assets held in institutional-grade custodial wallets (not self-hosted wallets) or managed by a qualified digital asset custodian
  • Asset inventory available, specifying blockchain networks, token standards, and custodial wallet addresses
  • Internal technology team or systems integrator available to implement the API connection
  • Regulatory status of digital asset holdings confirmed by legal counsel (securities token vs. utility token classification in applicable jurisdiction)

Process Steps

  1. Submit the Digital Asset Integration Request Form to your CIBC Mellon Digital Asset Services contact. Specify the blockchain networks, token types, and reporting outputs required.
  2. Receive API key provisioning through the CIBC Mellon developer portal. API keys are scoped to your organization and specific asset classes. Key rotation follows a 90-day cycle; automated rotation is available for production environments.
  3. Confirm supported blockchain networks and token standards. CIBC Mellon's platform currently supports EVM-compatible networks (Ethereum, Polygon, Avalanche), Solana, and permissioned enterprise networks (including R3 Corda and Hyperledger Fabric). Supported token standards include ERC-20, ERC-1155, and SPL. Requests for additional network support are submitted via a formal network onboarding request.
  4. Enroll custodial wallet addresses for each network in scope. Wallet address registration requires a signed attestation from your digital asset custodian confirming ownership of each address. Address enrollment is confirmed via a signed transaction or off-chain attestation per the platform's wallet verification protocol.
  5. Configure the real-time position feed. Agree on feed frequency (real-time via webhook, near-real-time at 15-minute polling, or end-of-day batch) and data schema (JSON/REST or FIX protocol for normalized position data). Token price feeds are sourced from approved data providers; configure your preferred price source hierarchy for valuation purposes.
  6. Schedule reconciliation reports to compare on-chain balances against CIBC Mellon's internal ledger. Reconciliation frequency options are daily, weekly, or intraday. Exceptions are flagged and routed to CIBC Mellon's Digital Asset Operations team for resolution.
  7. Complete sandbox testing using CIBC Mellon's test network environment. Validate position ingestion, price feed accuracy, reconciliation exception workflows, and report generation before enabling the production connection.
  8. Activate the production connection after successful sandbox sign-off. CIBC Mellon provides a technical implementation guide and dedicated support during the first 30 days.

Wallet Enrollment and Data Feed Configuration

Wallet Address Enrollment

  • Submit wallet addresses by blockchain network using the CIBC Mellon Wallet Registry form
  • Each address requires a custodian attestation confirming institutional ownership and control
  • Multi-signature wallet configurations must include the signing threshold and co-signatories list
  • Smart contract wallet addresses require ABI documentation for transaction decoding and event monitoring

Real-Time Position Feed Setup

CIBC Mellon's position feed aggregates on-chain data and normalizes it into your standard portfolio reporting schema. For tokenized securities, the feed maps on-chain token balances to ISIN or CUSIP equivalents where registry linkages exist. For non-standard token structures, a custom mapping table is configured during onboarding. All feed data is encrypted in transit using TLS 1.3 and at rest using AES-256.

Reconciliation Report Scheduling

  • Daily reconciliation: End-of-day on-chain balance vs. CIBC Mellon ledger; delivered by 08:00 local time
  • Intraday reconciliation: Available for high-frequency DeFi or tokenized cash positions
  • Exception report: Delivered alongside reconciliation; lists unmatched positions, price feed gaps, and unrecognized transactions
  • Regulatory reporting outputs: Available for MiCA-compliant asset reporting (EU) and applicable SEC guidance on digital asset disclosures (US)
