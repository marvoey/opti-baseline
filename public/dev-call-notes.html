curl https://YOUR-VERCEL-APP.vercel.app/api/opal/discovery
Execution - what Mark calls
curl -X POST https://YOUR-VERCEL-APP.vercel.app/api/opal/tools/fetch_cms12_content \
  -H "Content-Type: application/json" \
  -d '{"content_id":"1042","expand":"*","language":"en"}'

What lands with developers

  • A plain Next.js route. Nothing changes in your .NET code.
  • Read-only, with input checks: an ID pattern, an allow-list for sub_path, a 512-character cap.
  • expand defaults to *, so nested blocks come back in one call.
  • Errors return HTTP 200 with success: false, so Mark can read the message.
  • It calls the same engine as the live API route, so the tool and the API cannot drift apart.

SAY

"No copying and pasting. The agent fetched the page itself. And it's a plain Next.js route, so nothing changes in your .NET code."

SAY THIS BEFORE THEY ASK

"This route reads from a mock that follows the v3.0 contract. Pointing it at your environment means swapping one function for an HTTP call to your delivery endpoint."

Close

1 min

Go back to the ladder: Prompt, Agent, Skill, Tool, Workflow. Each step removed one manual job.

ASK

"What's the ticket your team keeps getting that you'd want to automate first?"

If someone asks...

Is this live CMS data?

No. The tool reads from a mock that follows the Content Delivery API v3.0 contract. Pointing it at your environment means replacing the engine call with an HTTP call to your delivery endpoint.

Can it change content in the CMS?

The tool you saw is read-only. A write tool would be a separate tool with its own guardrails, and you decide which agents can reach it.

Do we need to change our .NET code?

Not for this tool. It is a Next.js route that Mark calls over HTTP.

What about our cache?

Open question to settle together: point the tool at the same delivery endpoint the React app uses, or at a preview endpoint. Ask which they prefer.

Will the output be identical every run?

The table structure is fixed by the skill and agent. Wording and severity labels can vary a little between runs.

Something goes wrong live
  • Skill output looks different: check for the six columns and a breadcrumb per flagged block.
  • Tool does not appear: fall back to the attached JSON from Step 3 and show the route code in the tabs.
  • Clipboard blocked: select the text in the dark block and copy with Ctrl or Cmd + C.
