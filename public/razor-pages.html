The Preview Challenge: Server-Side .NET vs. Browser Canvas

Why can't a browser just open a .cshtml file and render it? Because Razor is a server-side template engine tightly bound to the ASP.NET Core runtime and Optimizely's content pipeline.

Dimension Canvas Native Preview .NET Razor (.cshtml) Execution
Execution Environment Client-side sandboxed browser iframe (HTML, Tailwind CSS, React, Next.js). ASP.NET Core Kestrel server, Roslyn compiler, and C# Dependency Injection.
Data Binding Mock JSON state or static DOM attributes rendered immediately. Requires Optimizely CurrentContent, IContentLoader, and RazorPageModel<T>.
On-Page Editing Helpers Visual HTML preview with interactive controls. Server-rendered @Html.PropertyFor(m => m.Heading) & ContentArea tags.
Recommended Pattern

Option A: The Dual-Artifact Pattern

Mark generates a visual HTML/Tailwind twin inside Canvas so the marketer can preview, tweak copy, and test responsive breakpoints in real time—while simultaneously maintaining the companion .cshtml and .cshtml.cs files for engineering.

  • check_circle Zero server compilation latency during ideation
  • check_circle 1:1 mapping between Tailwind DOM and Razor PropertyFor
Heavyweight Alternative

Option B: Sandbox .NET Compilation

Mark spins up a headless .NET runtime or RazorEngineCore inside its Linux VM, stubs out mock PageData models, compiles the Razor view, and pipes the rendered HTML string back to Canvas.

  • warning Requires mocking EPiServer.Core and Html.PropertyFor
  • warning Slower feedback loop for simple visual/copy iterations

Where This Fits: CMS 12 (PaaS) vs. CMS SaaS

Optimizely supports two distinct architectural paradigms. How Mark assists marketers depends on whether the customer runs coupled .NET MVC/Razor or modern headless Visual Builder.

Optimizely CMS 12 (.NET) terminal

Coupled MVC & Razor Pages

In CMS 12, templates are tightly coupled to C# Content Types. Historically, marketers have been locked into whatever Page Types and Content Areas developers built months ago.

How Mark Accelerates CMS 12:

• Scaffolds [ContentType] C# classes with data annotations.

• Generates RazorPageModel<T> & .cshtml templates.

• Gives marketers a live HTML preview to validate before submitting a dev ticket.

Optimizely CMS SaaS view_quilt

Visual Builder & Composition

In CMS SaaS, the paradigm moves away from server-side Razor views toward headless frontends (Next.js / React) and the Visual Builder Composition Model.

How Mark Accelerates CMS SaaS:

• Marketers assemble experiences via Sections, Rows, Columns, and Elements.

• Mark generates structured JSON Blueprints or Next.js components backed by Optimizely Graph.

• No Razor compilation required.

Pages/Product.cshtml.cs (RazorPageModel<T>) 
using EPiServer.Core;
using EPiServer.Web.Mvc;
using Microsoft.Extensions.DependencyInjection;

namespace AlloyMvcTemplates.Pages
{
    public class ProductModel : RazorPageModel<ArticlePage>, IPageViewModel<ArticlePage>
    {
        public ArticlePage CurrentPage => CurrentContent;

        public LayoutModel Layout { get; set; }
        public IContent Section { get; set; }

        public void OnGet()
        {
            Layout = HttpContext.RequestServices
                .GetService<PageViewContextFactory>()
                .CreateLayoutModel(CurrentContent.ContentLink, HttpContext);
        }
    }
}
